# 导入地图配置

配置导入适合创建同一玩法的地图变体。它可以复制地图设置、队伍商店和起始装备，但不会复制世界建筑、地图边界、出生点或爆破区。

## 打开导入页

在地图详情页进入“管理 → 导入地图配置”。页面列出当前服务器已加载的兼容地图，也会扫描 FPSMatch 数据目录中的其他世界存档。选择一个来源后，可以分别启用：

- 地图设置。
- 商店数据。
- 起始装备。

导入需要连续确认覆盖内容。操作成功后直接保存目标地图数据，不能从界面执行自动撤销。

## 来源如何匹配

来源必须与目标使用同一个游戏类型，且不能是目标地图自身。已加载地图按游戏类型筛选；历史存档还要求其保存分组与目标地图相符。

商店和起始装备按**队伍内部名称**映射。来源和目标都有同名队伍，并且双方具有相应能力时，才会复制该队数据。无法映射的队伍会被跳过，成功消息会显示跳过数量。

## 三类导入内容

### 地图设置

目标地图的每一个设置都必须能在来源配置中找到并按目标字段类型解析。玩法版本增加或删除设置后，旧存档可能不再能完整导入设置。

### 商店

目标队伍必须已经初始化商店。来源商店需要与目标商店类型、分类和槽位结构兼容。导入复制商品模板和相关配置，不复制某个玩家本局的金钱、购买次数或锁定状态。

### 起始装备

目标队伍需要 `StartKitsCapability`。导入会用来源的完整物品栈列表替换目标队伍当前装备，而不是追加到列表末尾。

## 不会导入的内容

地图区域、维度、地图 ID、出生点、爆破区、结束传送点和世界方块都不会改变。导入服务刻意把空间数据留给目标地图，避免把另一座建筑的坐标套到当前世界。

历史来源从游戏目录下的 `fpsmatch` 存档目录发现。损坏、过大或无法识别的 JSON 文件会被跳过；页面最多展示 256 个可用来源。

导入前若需要保留当前配置，应先由服务器管理员备份对应 FPSMatch 数据目录。存档组织见[保存与维护](persistence.md)。
