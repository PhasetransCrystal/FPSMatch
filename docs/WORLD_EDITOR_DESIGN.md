# 世界沙盘编辑器设计草案

状态：方案阶段，尚未实现。用户已选择「实际世界视口：自由镜头、俯视地图、点击和拖动点位」。

## 目标与工作流

在 Minecraft 实际世界画面上编辑地图配置。管理员打开地图编辑器后，通过自由镜头观察地图，选择出生点、方向箭头和区域边框，直接拖动或输入数值，预览后统一保存。

典型流程：选择地图 → 聚焦 CT 出生区 → 点击地面新增出生点 → 调整朝向 → 拖动爆破区边框 → 撤销一次误操作 → 保存 → 重开确认配置。

一期编辑对象为队伍出生点、地图边界、爆破区域。后续加入商店区域、比赛结束传送点、入场演员布局和镜头关键帧。方块建造不属于本期范围。

## 界面与操作

沿用项目已有 ModernUI，世界作为主画面，工具面板覆盖在画面边缘。首期保持完整世界渲染尺寸，拾取计算使用真实画面尺寸及 GUI 缩放；点击面板时不触发世界操作。

| 位置 | 内容 |
| --- | --- |
| 顶部 | 地图名称、选择/新增/移动工具、吸附、撤销/重做、保存、退出 |
| 左侧 | 按队伍和对象类型分组的对象列表、显示/隐藏、锁定 |
| 中央 | 实际世界、点位标记、朝向箭头、区域边框、操作手柄 |
| 右侧 | 选中对象的坐标、朝向、所属队伍或区域端点 |
| 底部 | 操作提示、坐标、草稿状态、区块加载与保存结果 |

- 左键选择；新增模式下点击已加载地面放置点位。重叠对象可通过对象列表明确选择。
- 右键按住后捕获鼠标，用 WASD/QE 飞行；释放后恢复指针。滚轮调整飞行速度。
- Alt + 左键围绕焦点旋转；中键平移；F 聚焦对象；俯视按钮切换到朝下的透视视角。正交投影后续单独评估。
- 点位支持地面拖放及轴向移动手柄；区域支持移动整体和拖动边界手柄。朝向用箭头与数值修改。
- 坐标吸附可切换整格、半格和自由；出生点默认落在方块顶面的水平中心，区域沿用现有整数方块边界语义。
- Ctrl+Z / Ctrl+Y 撤销和重做。一次连续拖动只产生一条历史记录，输入框获得焦点时快捷键优先交给输入框。
- Esc 先取消当前拖动，再处理退出；有草稿时提供保存、放弃与继续编辑。

## 与现有项目的关系

FPSMatch 提供通用编辑底座，业务通过适配器接入。现有地图数据仍是正式配置来源。

已有基础包括 `SpawnPointCapability`、`BaseMap.getMapArea()`、`DemolitionModeCapability`、`MapRoomActionService`、点位/区域预览渲染，以及 ModernUI。出生点现有交互部分绑定工具物品，需要提取为服务端编辑服务，不能让沙盘伪造手持工具调用。

建议模块：

- `WorldEditorScreen`：面板、焦点与输入路由。
- `EditorCameraRig`：自由、环绕、俯视与聚焦，通过 `CameraDirector` 使用相机。
- `EditorDocument`：基线快照、草稿对象、选中状态和撤销记录。
- `EditorObjectAdapter`：对象属性、展示、校验及正式配置映射。
- `EditorOverlayRenderer` / `EditorPicking`：标记、操作手柄及鼠标射线拾取。
- `MapEditService`：服务端授权、快照、冲突检测、提交与持久化结果。

编辑器向相机系统申请独立会话，建议优先级 50，低于死亡 100 和过场 200。失去相机控制权时暂停编辑并保留草稿，不自动争抢镜头。只有没有参与进行中的比赛、且具有地图管理权限的玩家才能进入；比赛启动、维度切换、退服会结束有效编辑会话。

后续镜头预览由编辑器自己的 rig 切换采样模式，结束后恢复编辑镜头姿态。现有相机系统只有一个临时会话，不能假设播放另一个会话会自动恢复被替换的编辑器会话。

## 草稿、保存与多人

打开时服务端下发地图快照和版本标识。拖动只更新本地草稿，点击保存才提交整个配置变更。客户端不直接覆盖服务端文件。

一期可使用规范化配置摘要做版本标识，覆盖本期涉及的点位和区域数据。提交时重新计算，能发现旧命令和工具造成的外部修改；不能只在新编辑器保存时递增版本。

对象使用本地稳定 ID，适配器保留其基线来源。现有按数组索引存储的数据无需立即迁移 UUID；删除、重排不能改变当前选中对象身份。

服务端在主线程再次检查权限、维度、比赛状态、基线版本、队伍、坐标合法性和请求规模。先验证全部变更，再统一应用。冲突时保留草稿，提示重新加载，不静默覆盖。

保存服务需要可传播的成功/失败结果。当前部分保存入口自行记录异常，不能直接把方法返回当作写盘成功。实现时需明确写盘失败的回滚或恢复策略，成功响应须在持久化完成后发送。

## 区块加载与建筑遮挡

独立相机不会自动让服务器向客户端发送远处区块。仅移动镜头无法保证整张地图可见，这是第一阶段必须验证的边界。

一期先限定在客户端已接收的地图范围内：显示未加载状态，不允许把未加载区域当作地面拾取。提供明确的「前往此处」操作，通过服务端校验后移动管理员的真实玩家位置以加载对应区域；这属于真实传送，界面须明确表达。关闭编辑器正常释放镜头，不以恢复旧坐标覆盖期间的死亡、重生或服务端传送。

后续可增加以编辑相机为中心、范围受限的区块订阅；必须同时处理客户端接收、缓存和退出释放，仅给服务端增加强加载票据不够。

一期通过飞入室内、对象列表、隐藏图层和选中对象高亮处理多层建筑。楼层裁切需要专门世界渲染支持，作为后续功能。

## 实施顺序与验收

1. 完成编辑器入口、镜头与输入、只读对象展示，确认已有相机策略允许界面内导航。
2. 完成出生点增删、拖动、朝向、属性面板和撤销重做。
3. 完成地图边界与爆破区编辑、服务端统一提交及冲突处理。
4. 在测试存档验证保存后重载一致，再验证多人同时编辑、权限变化和旧工具修改时的冲突。

必须验收：GUI 缩放后的拾取；一次拖动一次撤销；输入框不驱动镜头；未加载区域不误放点；非法/冲突请求不部分写入；死亡、过场抢占、退出重进无镜头或输入残留；游戏内实际出生位置、朝向和爆破区与编辑结果一致。

一期完成后，优先接入商店区域和入场布置，再把关键帧与时间轴放进同一编辑器。
